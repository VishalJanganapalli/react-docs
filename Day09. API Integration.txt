REACT - DAY 9: API INTEGRATION

An API lets a React application exchange data with another service. A request
is sent to an endpoint; the response usually contains a status code and data.

This lesson uses JSONPlaceholder for practice:
https://jsonplaceholder.typicode.com

Its write requests return example responses but do not permanently save changes.
Use your own authorized API for real data.

============================================================
1. HTTP METHODS
============================================================

GET     Read data.
POST    Create data.
PUT     Replace or update a resource.
DELETE  Remove a resource.

Common response status codes:

200 - Request succeeded.
201 - Resource created.
204 - Request succeeded with no response body.
400 - Request was invalid.
401 - Authentication is required or failed.
403 - Request is not allowed.
404 - Resource was not found.
500 - Server error.

============================================================
2. FETCH API
============================================================

fetch is built into browsers; no package installation is required. It returns
a Promise. Importantly, fetch does not reject just because the server returns
an HTTP error status such as 404. Check response.ok before using the data.

const API_URL = "https://jsonplaceholder.typicode.com/posts";

async function getPosts() {
  const response = await fetch(API_URL);

  if (!response.ok) {
    throw new Error(`GET failed with status ${response.status}`);
  }

  const data = await response.json();
  if (!Array.isArray(data)) {
    throw new Error("Expected the API to return a list of posts.");
  }

  return data;
}

============================================================
3. POST, PUT, AND DELETE WITH FETCH
============================================================

POST - send JSON in the request body and set the content type.

async function createPost(post) {
  const response = await fetch(API_URL, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(post)
  });

  if (!response.ok) {
    throw new Error(`POST failed with status ${response.status}`);
  }

  return response.json();
}

PUT - include the resource ID in the URL and send the updated representation.

async function updatePost(id, post) {
  const response = await fetch(`${API_URL}/${id}`, {
    method: "PUT",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(post)
  });

  if (!response.ok) {
    throw new Error(`PUT failed with status ${response.status}`);
  }

  return response.json();
}

DELETE - check the status, but do not assume there will be JSON to parse.

async function deletePost(id) {
  const response = await fetch(`${API_URL}/${id}`, {
    method: "DELETE"
  });

  if (!response.ok) {
    throw new Error(`DELETE failed with status ${response.status}`);
  }
}

If an API returns status 204, there is no response body; do not call
response.json() for that response.

============================================================
4. ASYNC/AWAIT AND ERROR HANDLING
============================================================

Use try/catch around asynchronous requests so that network errors, invalid JSON,
and errors thrown after checking response.ok can be shown to the user.

async function loadPosts() {
  try {
    const posts = await getPosts();
    return { posts, error: "" };
  } catch (error) {
    const message = error instanceof Error
      ? error.message
      : "An unexpected error occurred.";
    return { posts: [], error: message };
  }
}

Keep different kinds of failure understandable:
- HTTP error: the server responded with a non-success status.
- Network error: the browser could not complete the request.
- Response error: the body was not valid JSON or did not match expectations.

Do not treat an empty list as proof that a request succeeded; keep the error
state separate from the data.

============================================================
5. AXIOS INTRODUCTION
============================================================

Axios is a Promise-based HTTP client. Install it in the project before using it:

npm install axios

import axios from "axios";

async function getPost(id) {
  const response = await axios.get(
    `https://jsonplaceholder.typicode.com/posts/${id}`
  );

  return response.data;
}

Axios puts the response payload in response.data. Unlike fetch, Axios rejects
the Promise for non-2xx HTTP responses by default.

Examples of the other methods:

async function updatePostExamples() {
  const created = await axios.post(API_URL, {
    title: "React API lesson",
    body: "Practice POST requests.",
    userId: 1
  });

  const updated = await axios.put(`${API_URL}/1`, {
    id: 1,
    title: "Updated title",
    body: "Updated post body.",
    userId: 1
  });

  await axios.delete(`${API_URL}/1`);
  return { created: created.data, updated: updated.data };
}

For Axios errors, use axios.isAxiosError(error) and inspect error.response
when the server responded. error.response may be absent for a network failure.

============================================================
6. FETCH DATA IN useEffect
============================================================

Use an effect for loading data after a component mounts. Track loading, data,
and error separately. Abort an in-flight request if the component unmounts.

import { useEffect, useState } from "react";

function PostsList() {
  const [posts, setPosts] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");

  useEffect(() => {
    const controller = new AbortController();

    async function loadPosts() {
      setLoading(true);
      setError("");

      try {
        const response = await fetch(
          "https://jsonplaceholder.typicode.com/posts",
          { signal: controller.signal }
        );

        if (!response.ok) {
          throw new Error(`Request failed with status ${response.status}`);
        }

        const data = await response.json();
        if (!Array.isArray(data)) {
          throw new Error("Expected the API to return a list of posts.");
        }

        setPosts(data);
      } catch (requestError) {
        if (!controller.signal.aborted) {
          const message = requestError instanceof Error
            ? requestError.message
            : "An unexpected error occurred.";
          setError(message);
        }
      } finally {
        if (!controller.signal.aborted) {
          setLoading(false);
        }
      }
    }

    loadPosts();
    return () => controller.abort();
  }, []);

  if (loading) return <p>Loading posts...</p>;
  if (error) return <p role="alert">Could not load posts: {error}</p>;
  if (posts.length === 0) return <p>No posts found.</p>;

  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  );
}

The empty dependency array runs the effect after the initial render. If the
request depends on a value, include that value in the dependency array and
request the matching data when it changes.

============================================================
7. API RESPONSE HANDLING CHECKLIST
============================================================

- Check the HTTP status before treating a fetch response as successful.
- Parse JSON only when the endpoint returns a JSON body.
- Confirm the response has the shape the UI expects.
- Keep loading, error, and successful data states separate.
- Render lists with stable keys from the returned records.
- Cancel requests that no longer belong to a mounted component.
- Never put private API secrets in browser code.
- Handle authentication and server-side validation on the server.

============================================================
DAY 9 SUMMARY
============================================================

- Use fetch or Axios to send HTTP requests.
- Use GET, POST, PUT, and DELETE for the appropriate operations.
- Use async/await and handle both HTTP and network errors.
- Fetch API calls in useEffect with cleanup when needed.
- Show loading, error, empty, and success states in the UI.

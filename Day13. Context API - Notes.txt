What is Multiple Context?
Instead of creating one giant Context for everything, we create multiple Contexts, 
where each Context is responsible for one feature.

Think of it like departments in a company.

Company
├── HR Department
├── Finance Department
├── Sales Department
└── Marketing Department

Each department has its own responsibility.

Similarly, in React:
Application

├── AuthContext
├── ThemeContext
├── CartContext
└── LanguageContext

Each Context manages only one type of data.


| **Provider**      | **Purpose / Responsibility**                       | **Data & Functions Shared**                         | **Example `value`**                                                 |
| ----------------- | -------------------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------- |
| **AuthProvider**  | Handles authentication and user-related data.      | • Logged-in User<br>• Login<br>• Logout<br>• Token  | <AuthContext.Provider value={{user,login,logout<br>  }}             
| **ThemeProvider** | Handles the application's theme (Dark/Light mode). | • Theme<br>• Change Theme                           | <ThemeContext.Provider  value={{theme,setTheme  }}                       
| **CartProvider**  | Handles shopping cart functionality.               | • Cart Items<br>• Add to Cart<br>• Remove from Cart | <CartContext.Provider value={{cart,addToCart,removeFromCart<br>  }} 



Why not keep everything in one Context?

Suppose you make one big Context.
<AppContext.Provider
    value={{ user, theme, cart, products, language, notifications, login, logout, addToCart, removeFromCart, fetchProducts}}
>

Problem 1 : Difficult to Maintain
Problem 2 : Hard to Understand
Problem 3 : Unnecessary Re-rendering
Problem 4 : Poor Reusability


<AuthProvider>
    <ThemeProvider>
        <CartProvider>
            <App />
        </CartProvider>
    </ThemeProvider>
</AuthProvider>






==========================================================
EXAMPLE 1: Context contains the API call
==========================================================

Folder Structure

src/
 ├── context/
 │    └── UserContext.jsx
 ├── components/
 │    ├── UserList.jsx
 │    └── App.jsx


----------------------------------------------------------
UserContext.jsx
----------------------------------------------------------

import { createContext, useContext, useEffect, useState } from "react";
import axios from "axios";

const UserContext = createContext();

export const UserProvider = ({ children }) => {
  const [users, setUsers] = useState([]);

  const fetchUsers = async () => {
    const response = await axios.get(
      "https://jsonplaceholder.typicode.com/users"
    );

    setUsers(response.data);
  };

  useEffect(() => {
    fetchUsers();
  }, []);

  return (
    <UserContext.Provider value={{ users }}>
      {children}
    </UserContext.Provider>
  );
};

export const useUserContext = () => useContext(UserContext);


----------------------------------------------------------
App.jsx
----------------------------------------------------------

import { UserProvider } from "./context/UserContext";
import UserList from "./components/UserList";

function App() {
  return (
    <UserProvider>
      <UserList />
    </UserProvider>
  );
}

export default App;


----------------------------------------------------------
UserList.jsx
----------------------------------------------------------

import { useUserContext } from "../context/UserContext";

function UserList() {
  const { users } = useUserContext();

  return (
    <>
      {users.map((user) => (
        <p key={user.id}>{user.name}</p>
      ))}
    </>
  );
}

export default UserList;


----------------------------------------------------------
Flow
----------------------------------------------------------

Context
   │
   ├── API Call
   │
   ├── setUsers(response.data)
   │
   └── Provider
           │
           ▼
      UserList

EXAMPLE 2: API File + Context
==========================================================

Folder Structure

src/
 ├── api/
 │    └── userApi.js
 ├── context/
 │    └── UserContext.jsx
 ├── components/
 │    ├── UserList.jsx
 │    └── App.jsx


----------------------------------------------------------
userApi.js
----------------------------------------------------------

import axios from "axios";

export const getUsers = () => {
  return axios.get(
    "https://jsonplaceholder.typicode.com/users"
  );
};

Notice this file only returns the API response.


----------------------------------------------------------
UserContext.jsx
----------------------------------------------------------

import { createContext, useContext, useEffect, useState } from "react";
import { getUsers } from "../api/userApi";

const UserContext = createContext();

export const UserProvider = ({ children }) => {
  const [users, setUsers] = useState([]);

  const fetchUsers = async () => {
    const response = await getUsers();

    setUsers(response.data);
  };

  useEffect(() => {
    fetchUsers();
  }, []);

  return (
    <UserContext.Provider value={{ users }}>
      {children}
    </UserContext.Provider>
  );
};

export const useUserContext = () => useContext(UserContext);


----------------------------------------------------------
UserList.jsx
----------------------------------------------------------

import { useUserContext } from "../context/UserContext";

function UserList() {
  const { users } = useUserContext();

  return (
    <>
      {users.map((user) => (
        <p key={user.id}>{user.name}</p>
      ))}
    </>
  );
}

export default UserList;


----------------------------------------------------------
Flow
----------------------------------------------------------

UserList
    ▲
    │
Context
    │
    ├── getUsers()
    │
API File
    │
    ├── axios.get(...)
    │
    ▼
Response
    │
Context
    │
setUsers(response.data)
    │
Provider
    │
UserList



==========================================================
Difference
==========================================================

| Context does API | API File + Context |
|------------------|--------------------|
| API code is inside Context | API code is in a separate file |
| Harder to reuse | Easy to reuse across multiple contexts/components |
| Context becomes larger | Cleaner separation of responsibilities |
| Good for small apps | Best practice for medium/large apps |


==========================================================
Best Practice (Most React Projects)
==========================================================

API File
    │
    ▼
Context
    │
Stores state
    │
    ▼
Components


In other words:

- API file: Knows how to fetch data.
- Context: Knows how to store and share the data.
- Components: Only consume the shared data without worrying about where it came from.
